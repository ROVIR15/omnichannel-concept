SYMPTOM
-------

  Error: ConnectionError (53000): Raised whenever a signaling connection error
  occurs that is not covered by a more specific error code.
Twilio.Device never reaches "registered".

CODE REVIEW
-----------
- src/voice/twilio.ts voiceToken(): HS256 JWT, header cty "twilio-fpa;v=1",
  iss = API Key SID, sub = Account SID, voice grant with outgoing
  application_sid + incoming allow. Format matches Twilio spec. OK.
- src/voice/routes.ts /api/voice/token: identity = user.id (string). OK.
- No CSP blocking connect-src to Twilio. OK.
Conclusion: token generation code is correct.

ROOT CAUSE
----------
The saved API Key Secret does not belong to API Key SKbd…507f. The browser
access token is signed with the wrong secret, Twilio rejects it and closes
the signaling WebSocket, and the SDK reports the generic 53000 error.

FIX
---
1. Twilio Console -> Account -> API keys & tokens -> create a new Standard key
   (the secret is shown only once, at creation).
2. Settings -> Twilio: paste the new API Key SID and its Secret together.
3. Reload /voice; expect "registered for incoming calls".
4. Optional: rerun check #1 to confirm the key/secret pair returns 200.
